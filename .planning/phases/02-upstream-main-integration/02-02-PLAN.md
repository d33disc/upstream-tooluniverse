<objective>
Build the isolated integration stage that criterion 1 requires: a detached worktree at the pre-merge fork parent `e0755067`, with upstream `56adcfd9` merged into it and every conflict re-derived independently under D-08's resolution rule. This is a review instrument, never a replacement (D-06) -- it exists so the resolutions that landed in `f81448f2` can be compared against resolutions arrived at from first principles, rather than taken on faith.

Purpose: `rev-list` already proves upstream is contained in the fork. What it cannot show is whether the 22 hand-resolved files clobbered fork behavior. Only an independently re-derived merge can answer that, and only an isolated stage can answer it without the main checkout's pre-existing dirty state contaminating the comparison.

Scope note: this plan builds the stage, starts the merge, and resolves the **data/config layer** -- the two conflicted `data/*.json` arrays, `default_config.py`, `pyproject.toml`, and `.gitignore`. The 11 conflicted Python adapter/core modules and 5 conflicted test files are plan `02-03`'s work, and the commit, the `refs/audit/remerge` pin, and the `tu build` regeneration land there too. The split is a sizing decision: 22 conflicted paths in one task exceeds the five-file ceiling and a single agent's useful context, and the data/config seam is the natural cut because those resolutions are mechanical set operations while the source-module ones are definition-level judgment.

Output: an isolated stage with a merge in progress, the data/config layer fully resolved under recorded D-08 rules, and a `remerge.json` evidence record of the conflict set, every resolution decision so far, and the handoff state.
</objective>
