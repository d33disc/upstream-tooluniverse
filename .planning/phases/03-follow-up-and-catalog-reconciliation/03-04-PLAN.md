Add `compare_import_sets(left_init_text, right_init_text)` and `run_regeneration_guard(repo_root, scratch_root)` to `scripts/audit_registration_chain.py`.

`compare_import_sets` is a pure function over two `tools/__init__.py` texts: parse each into its set of imported tool names, and return `{only_left, only_right, common, left_count, right_count, decreased}` with the name lists sorted. `decreased` is true when the right side has names missing that the left side had. `run_regeneration_guard` performs the whole comparison inside a disposable worktree, never in the main checkout:

1. Create a detached worktree at the current HEAD under a scratch root **outside the repository** (`git worktree add --detach <scratch>/regen-stage HEAD`). This is non-negotiable: `generate_coding_api.py` writes into `src/tooluniverse/tools/` by default, and the main checkout already holds 2,663 uncommitted files whose disposition is a human decision. Reuse Phase 2's stage pattern; do not invent a second isolation mechanism.
2. Run the regeneration twice inside that worktree and capture each run's produced `tools/__init__.py`: once with the ambient shell environment, and once with `.tooluniverse/tooluniverse-env.sh` sourced first so whatever credentials this machine does hold are loaded. Name one generator canonical for the guard and record which one and why in the output; if the other can also be redirected outside the source tree, run it too and record both, since research measured the two scripts as diverged and their outputs are not guaranteed identical. Bound each run with an explicit timeout and record the elapsed time and exit code; a timeout is a recorded finding, not a silent skip.
3. Compare every produced import set against the committed baseline read from `git show HEAD:src/tooluniverse/tools/__init__.py`.
4. Compare the ambient-environment run's import set against the **dirty working tree's** current `src/tooluniverse/tools/__init__.py`, read read-only. Record whether they match. A match is direct mechanical evidence that the pre-existing dirty state is the output of a credential-gated regeneration of this same commit, which answers RESEARCH.md Open Question 1; a mismatch means a third generation path exists and that is itself a finding.
5. Remove the disposable worktree (`git worktree remove --force`) and delete the scratch tree, in a `finally` block so a failure mid-run cannot leave a stray worktree registered.

**Decision B -- the two live duplicate public names.** `UniProt_get_proteome` is defined in both `src/tooluniverse/data/uniprot_tools.json` (category `uniprot`) and `src/tooluniverse/data/uniprot_proteomes_tools.json` (a live category entry), and `OpenMeteo_get_air_quality` is defined in both `src/tooluniverse/data/open_meteo_tools.json` (category `open_meteo`) and `src/tooluniverse/data/open_meteo_airquality_tools.json` (a live category entry). Plan 03-02 recorded these as `live_collision` findings and holds them open as a strict `xfail`; five further duplicates were classified as archived copies and need no decision.
  </decision>

  <context>
Why a human decides A: the state is another session's work in a shared checkout. Research established that it is stale and that it is a *regression* relative to HEAD -- it drops roughly eighty tools whose `required_api_keys` are unmet on this machine, because both generator scripts build their file list from `load_tools()`'s credential-filtered result. But "stale and wrong" does not by itself authorize destroying it, and committing over it would bake the regression into the catalog. Why a human decides B: D-05 draws the line explicitly. Stale generated entries are self-resolving under a clean regeneration; a duplicate public name across two different tool definitions is a genuine naming collision, resolved only after review and never silently reconciled. Picking a winner changes which schema and which implementation users get for that name, on both `get_tool_info` and every execution path -- Phase 2's D-06 posture applies directly.

Relevant reading before deciding: `evidence/staging/regeneration_guard.json`, `evidence/staging/chain/duplicates.json`, `03-RESEARCH.md` § "Concurrent State Investigation (D-06)" and § Pitfall 3, and `03-CONTEXT.md` D-05 and D-06.
